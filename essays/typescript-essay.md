Typescript as a language, does not seem all too complicated, as it is simply built on top of a base of Javascript, which could be considered as a simplified version of Java, and adds explicit types to the variables. This is not a bad thing; however, as it serves as a useful tool for people to use. As a language, it is reminiscent of C and Java and the like, as it progresses further along in how people further refine and optimize languages for various purposes. Just as Java is a more simplified version of C and Python is made to be a simpler experience to learn and use overall, Typescript just seems to me as another level of simplification for code. Of course, for its purposes that is completely fine, as from what I gather it is mostly used for website development and similar projects where this kind of simpler style would be more convenient since getting into the nitty gritty of everything doesn't matter as much and the focus can be on producing functioning software. Though of course, the basic bones of everything is practically there, so it is easy to learn and get into with minor syntax like variable declarations which are formatted and made simpler that can cause minor discomfort. Admittedly, I have not fully engaged with the language, so this is a rather surface level observation based upon me just dipping my toes into the language so to speak.

## Learning Typescript/Javascript

For my first foray into the language, I took a freeCodeCamp course which was a nice introduction to the language that I felt was pretty helpful with its demonstrations and interactive examples, even if it felt a little repetitive due to my prior experience with languages like Java, C, C++, and Python. Though I have harped upon the simplicity of the language, it is just a few minor things, such as variables not really necessitating type declarations, the clumping together of numerical variable types, and so on and so forth. As a beginning language, this simplicity makes it quite a bit more accessible to learn in the same vein as languages like Python, though of course it does depend on what you feel is most important when learning programming. A simpler language like Javascript and Python, and to a certain extent Java, makes it easier to try out and be able to do a lot of things without having to know and remember a lot of information and knowing much about the more technical aspects, so it isn't as daunting. On the other hand, you can easily argue for learning C first as many languages build off of the base of C, and learning the more tedious ways of C to begin before allowing yourself the easier shortcuts of other languages is a good way to start off. C is also quite simple at face value, but with C you do have to build everything you use from the ground up and learn how to use libraries to be able to really do anything. You need to know how C works because it will not handhold you through the process and often times will seem to be working properly, but is really just a false positive due to a coincidence. In order to engage with C you need to know what exactly the code is doing in order to be able to use it properly and debug because C will just do exactly what you tell it to with few warnings, even if you accidentally do something you did not mean to or something you should not do. The only way to tell if something is wrong is encountering a bug or if you do something the computer itself rejects. Order and structure become very important to pay attention to. Of course that is not to say you can just stumble your way through Javascript or Typescript because you do need to know what you're doing, at least at a surface level, to be able to parse through your code and see what is and is not working if it isn't giving the correct output. Javascript and Typescript just offer a more streamlined experience that languages have been going through as people continue to refine these types of languages for various purposes.

As a tool Javascript and Typescript are proficient at what they do. The simplicity doesn't really take away from their functionality, though I am not familiar with the more technical aspects for the differences between languages such as speed and runtime differences. Regardless, Javascript and Typescript are still very functional languages that you can program almost anything with. It just seems to me that Javascript or Typescript might not be the first choice for more precise projects, where it would be handier to have more specific labeling and increasingly complex situations. With my limited understanding of software engineering I feel that Javascript can be a useful language for development, especially for general maintenance of websites and such, where the simplicity works for it, as we are not trying to overcomplicate things, but rather display information in a secure and sometimes flashy way.

## Athletic Software Engineering

Athletic Software Engineering has been a somewhat interesting concept, but rather time consuming. It focuses a lot on personal responsibility, which admittedly is something I need to work on more. Whether it is effective will have to be seen, though it will be influenced by my own personal growth as well. The practice WODs work theoretically, but the real difficulty with the WODs is taking in the instructions and figuring out how to do them within the time limit. The first few homework ones were quite a bit simple, which didn't really help me in that aspect. The in-class practice, however, did show me that it can be more efficent to focus on getting the general idea and functionality done first and then ironing out details later. I think this style of teaching is rather effective on reinforcing and learning topics. The focus on personal responsibility, while an important lesson does hinge on the student being responsive to such a work ethic. I do feel the focus on time could maybe cause a few issues, but realistically is a skill that people will have to learn for jobs because the world is rough and slow and steady isn't always appreciated.

## Conclusion

This class certainly seems interesting and Javascript and Typescript will be another tool in my toolbox that I can use later. I might not fully enjoy the language, but over time the sense of incongruence will fade. Simplicity in itself is not an issue, and Javascript and Typescript showcase this as they serve as useful tools for their own purposes. I look forward to seeing what the semester brings and hope to come out of it for the better.
