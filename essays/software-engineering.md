When you think of software engineering, the first thing that comes to mind is just coding and building programs. That is not the whole story for software engineering though, it is also a practiced discipline that requires the appropriate mindset in order to create the best possible product as possible, like many other artforms. Coding, while a practice that can be done on one's lonesome, is often times a group effort, especially in professional scenarios, so software engineers must keep up to a standard so their code is legible and understandable by their peers. These are all aspects that can be extended beyond just software engineering into the grander scheme of life, as order, teamwork, and tidiness are all virtues that we should all aspire to. 

## Coding Standards

An important aspect to code that can often times get overlooked is readability. In the moment, as software engineers code, they may get absorbed in their work and not put much effort into how it looks because they themselves know what the code does. This does not work for group efforts, however, as no two people think the exact same way and will not always be able to tell what something is at first glance, so code being readable becomes very important. This is where coding standards comes in. Coding standards are just what they sound like, standards for coding. It is basically self-imposed syntax for code. It encompasses topics such as how much spacing is used, what elements are allowed on the same line, how you indent your lines, what new lines and blank spaces are allowed, and so on and so forth. These coding standards are meant to make code that much more readable for everybody, so that if a piece of code is passed around in a group for some sort of project, everybody is able to read it without too much trouble.

The underlying idea behind this concept is just basic tidiness and consideration, which more people should care about. Life is unfortunately a social experience, so everybody has to know how to interact and work with other people. The general rule of thumb is to not make things harder for other for other people, which is what this basically is. Communication is one of the most important skills someone can have, so you must keep in mind how each and every thing you say or do comes across to other people, much like how coding standards dictate how you code should look so that other people can read it. Improper communication can lead to the wrong idea being transmitted, causing many an unwanted consequence. Making youself and you code presentable is just basic courtesy in the larger game of life and work.

## Agile Project Management

In a similar vein Agile Project Management is an organization method to help work towards a goal by breaking it down into smaller goals. In the course I took, we focused on Issue Driven Project Management, which was an organization style for smaller groups to work towards developing software. The basic idea was regular meetings at least twice a week, divinding work into smaller tasks that would be completed in regular intervals of a few days, proper documentation, and individual work ethic. In this style, every member is constantly working on something and is able to regularly communicate and share results to work towards a bigger goal. Each step pushing the project a little futher along. This is just good planning and organization to work towards a goal that encourages efficient teamwork and procrasting as little as possible. This is just another important aspect of life. Things keep moving, and we all have to keep moving forward and completing our goals. Even if an issue seems so large and insurmountable, we can always break it down and take it a little at a time.

## Conclusion

As with everything in life, there is much to be learned from software engineering, other than the topic itself. Everything you learn is an opportunity to grow more as a person. The very basic concepts of software engineering is just organization and task completion, whether that be by yourself or in a group. As long as we keep going at it and think critically about what we are doing and why we are doing it, we can accomplish anything.
